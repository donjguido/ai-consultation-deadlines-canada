## 3. Friction log

Ranked roughly by cost. Each entry: what happened, what I did instead, the fix.

**1. `docs/FORK-RUBRIC.md` is not committed.**
*Where:* the clone. *What happened:* the rubric I was asked to score against exists in the
author's working tree but is absent from the cloned repo. *What I did:* read it out of the
original checkout. *Fix:* `git add docs/FORK-RUBRIC.md` and link it from `FORKING.md` — a
fork attempt that cannot see the rubric cannot self-score, which is the whole point of it.

**2. The test suite hardcodes the original's name, so every fork is born red — and the fix
requires a test edit.**
*Where:* `tests/test_fork.py:77` and `:82`. *What happened:* `fork.py` writes `forks.yaml`
listing *the site being forked from* (read live from the `site.yaml` it is about to
overwrite), but the test asserts the literal string "AI Consultation Deadlines Canada". In an
Ontario checkout the parent is Ontario, so both assertions fail forever:
`AssertionError: the original is linked as a sister site`. Line 76's
`assert "Canada" not in body_only` has the same shape. *Consequence:* `pytest` is red on a
clean fork, and `daily.yml` runs `pytest` before anything else, so **a scaffolded fork's
workflow never deploys**. *What I did:* edited `tests/test_fork.py` to read the parent's name
from the copy's `site.yaml` before the scaffold overwrites it, and marked "Python/test edits:
0" as failed. *Fix (three lines, in the original):* capture
`parent = yaml.safe_load((copy / "data" / "site.yaml").read_text(encoding="utf-8"))["name"]`
before calling `fork.main(...)`, then assert `parent in footer` and
`forks["forks"][0]["name"] == parent` instead of the literals.

**3. Step 6 of the scaffold's own checklist crashes on the file the scaffold just wrote.**
*Where:* `python -m pipeline.fetch data/candidates.json` on a fresh scaffold. *What
happened:* the generated `sources.yaml` has a `sources:` key followed only by comments, so
`yaml.safe_load` yields `{"sources": None}` and `fetch.py:268` dies with
`TypeError: 'NoneType' object is not iterable` — a stack trace with no hint that the cause is
an empty source list. `test_fork.py:68` even *asserts* that `sources["sources"] is None`, so
the crash is enshrined. *What I did:* recognised it and wrote real sources. *Fix:* in
`fetch.py`, iterate `SOURCES.get("sources") or []`, and when the list is empty print
"data/sources.yaml has no enabled sources yet — see docs/FORKING.md" and exit 0.

**4. `classifier.official_names` is deleted by the scaffold, demanded by the checklist, and
documented nowhere.**
*Where:* `fork.py:175` pops it; `fork.py:207` says "Fill `classifier.official_names`".
*What happened:* the checklist tells you to fill a key whose purpose, shape (free-text
instruction? a mapping? a list?) and audience are not stated in FORKING.md, README.md or the
generated file — and the scaffold has just destroyed the only worked example. **This is the
question I most wanted to ask the author.** *What I did:* read the original `site.yaml` out of
the parent checkout to see it was a free-text sentence appended to the translation
instruction, then read `classify.py:70` to confirm. *Fix:* do not pop it; replace it with a
commented placeholder carrying the original's example, and add a row to the FORKING.md table.

**5. `pipeline/fork.py` destroys every explanatory comment in `site.yaml`.**
*Where:* `fork.py:188`, `yaml.safe_dump(site, ...)`. *What happened:* the original
`site.yaml` carries 24 comment lines documenting `slug`, `level`, `schema_type`, `primary`,
`secondary`, `locales`, the `text` block's fallback rule, `keywords` and the whole
`classifier` block. The scaffolded file has three lines of header and nothing else, which is
what makes B3 fail — a forker gets a *less* documented file than the one they cloned. *What
I did:* diffed against the original to recover the meanings. *Fix:* cheapest version is a
constant block of comments re-emitted above each top-level key after `safe_dump`; the better
one is to template `site.yaml` as text with placeholders (the way `SOURCES_TEMPLATE` and
`FORKS_TEMPLATE` already are in the same file) rather than round-tripping through YAML.

**6. The keyword pre-filter silently ignores prefix fragments — including two shipped ones.**
*Where:* `fetch.py:41`, which compiles `\b( ...all fragments joined by | ... )\b`. *What
happened:* the trailing `\b` means any fragment that ends mid-word can never match. The
shipped `biom[ée]tri` does not match "biométriques"; `d[ée]cision automatis` does not match
"décision automatisée". Verified in the unmodified repo: `relevant("données biométriques")`
returns False. This is a live false negative in the Canadian site too, and it is invisible —
exactly the failure mode FORKING.md warns about, caused by the tool itself. *What I did:*
rewrote my fragments with an explicit `\w*` suffix. *Fix:* drop the wrapping `\b(...)\b`
(fragments that want boundaries already carry their own, e.g. `\bAI\b`), or at minimum
document in `site.yaml` and FORKING.md that each fragment is wrapped in word boundaries and
must therefore end on one.

**7. Nothing tells you to delete the inherited `site/`, and the build never cleans it.**
*Where:* `pipeline/build.py`, step 7 of the checklist. *What happened:* a fork clones the
original's fully rendered `site/`. The build overwrites what it writes and leaves everything
else, so my first monolingual build shipped the parent's `feed-fr.xml`, `digest-fr.md` and
`deadlines-fr.ics` alongside the new English-only output. Nothing warns you, and
`test_build.py` builds into a temp directory so it never sees this. *What I did:* removed
`site/` before the real build. *Fix:* add that line to the scaffold's checklist, have
`fork.py` empty `site/` the way it empties `items.json`, or have the build delete artefacts
for languages that are no longer configured.

**8. A misconfigured source is a silent zero or a bare KeyError.**
*Where:* `fetch.py` `_record` and `fetch.py:272`. *What happened:* `title: titel` (one typo in
a column map) returns 0 rows with no message — indistinguishable from a source that genuinely
had nothing. An invalid `kind` prints "data_catalogue FAILED: 'jsonapi'", which does not say
that `kind` is the problem or what the valid values are. Both cost me a round of guessing.
*Fix:* in `_record`, when the title column resolves to None for the *first* row, print once
per source: "<key>: column 'titel' not found; row has: [first dozen keys]". And validate the
kind up front with a ValueError naming the key, the bad kind and `sorted(FETCHERS)`.

**9. `html_index` runs the pre-filter on the link text only, which makes it useless for two
of Ontario's three scrapeable pages.**
*Where:* `fetch.py:243`, `if not href or not title or not relevant(title)`. *What happened:*
FORKING.md presents `html_index` as "the model for anything that has no feed", but it never
fetches the linked page before deciding relevance. On ero.ontario.ca the link texts are
instrument names ("Vale Canada Limited - Environmental Compliance Approval (air)") — 0 of 20
kept. On ontario.ca's consultations directory the link texts are "Participate" and "Read about
the consultation" — 0 of 91 kept. Only `sitemap`, which fetches the page and filters on its
text, actually works. **This is the second question I wanted to ask the author** — is the
title-only filter deliberate cost control, or an oversight? *What I did:* moved to a `sitemap`
source over ontario.ca's sitemap index, and left the two `html_index` sources enabled with a
comment recording the zero. *Fix:* give `html_index` the same `fetch_pages: true` option that
`rss` has, and say plainly in FORKING.md that without it the pre-filter sees the anchor text
and nothing else.

**10. `python -m pipeline.classify` has no `--help` and no way to inspect the prompt.**
*Where:* `classify.py:155`. *What happened:* running it bare gives
`IndexError: list index out of range` from `sys.argv[2]` instead of a usage line, and there is
no supported way to see the prompt your `classifier` block produces without an API key.
*What I did:* imported `build_system_prompt(SITE)` from a Python one-liner. *Fix:* an argparse
front end with `--print-prompt` that dumps the system prompt and exits — the cheapest possible
way for a forker to check rubric E1 before spending a token.

**11. `limit` on a `sitemap` source does not mean what the docs say.**
*Where:* FORKING.md ("`limit` caps pages fetched per run") versus `fetch.py:216`, which
breaks when `len(out) >= limit` — that is, against *kept* items, checked before the page fetch.
*What happened:* I set `limit: 60` expecting a 60-page crawl; the fetcher will actually fetch
every matching URL until 60 survive the filter, which on a low-hit-rate pattern is unbounded.
*What I did:* counted the matching URLs by hand first (96, so it was safe). *Fix:* one phrase
in FORKING.md ("caps how many items a source contributes"), or add a separate `max_pages`.

**12. The scaffold leaves the original's identity in `README.md` and `CHANGELOG.md`.**
*Where:* the checklist. *What happened:* after the scaffold, `README.md` still says "AI
Consultation Deadlines Canada", links the original's live URL and carries the original
author's copyright line; `CHANGELOG.md` is the original's history. Neither is mentioned in the
nine steps. *What I did:* left them, since the rubric's file list excludes them. *Fix:* add a
step 0 — "rewrite README.md, reset CHANGELOG.md, check the licence footer" — or have `fork.py`
emit a short fork-flavoured README.

**13. The `--dry-run` does not print the checklist.**
*Where:* `fork.py:185`, `if args.dry_run: return plan`. Minor: you cannot preview what you
will be asked to do next. *Fix:* return the checklist in the dry-run output too.

**14. `gazette_notice` is a federal-Canada word baked into the closed `type` enum.**
*Where:* `models.py:30`, `test_config.py:69`, and both strings files. *What happened:* every
fork inherits a "Gazette notice" type label whether or not its jurisdiction has a gazette, and
the enum is guarded by a test so it cannot be changed from `data/`. Ontario does have a
gazette so it cost me nothing, but a fork of, say, a US state would ship a dead label it
cannot remove. *Fix:* rename it to something jurisdiction-neutral (`official_notice`), or let
the `type` vocabulary be extended from `site.yaml`.

**15. There is no way to build an item URL from a template, which CKAN-shaped APIs need.**
*Where:* `_record`, `cfg["columns"]["url"]`. *What happened:* CKAN returns a slug (`name`),
not an absolute URL. `columns.url` can only read an existing field, and `portal` gives every
row the *same* URL. I mapped `url: resources.0.url`, which points at a spreadsheet rather than
the dataset page, and rows with no resources fell back to the API URL. *Fix:* support
`url_template: https://data.ontario.ca/dataset/{name}` in `columns`, formatted from the row.
(Credit where due: dotted paths already accept list indices — `resources.0.url` — which is
neat, and undocumented.)

## 4. What went well

- **The three-data-files promise is basically true.** Everything that is *content* — identity,
  prose, both languages, licence, classifier scope, keywords, sources — really did live in
  `data/`. I never once wanted to change `build.py`, `models.py` or the template.
- **`pipeline/fork.py` is genuinely good at the part it does.** One command, a correct
  `--dry-run`, and the resulting `site.yaml` was valid, Ontario-flavoured, and had no leftover
  identity. Rubric A4 passed on the first try.
- **The multilingual plumbing is the strongest thing here.** Writing a real French `text`
  block was the *only* translation work; feeds, calendars, digests, hreflang, x-default, the
  en-CA/fr-CA locales and the per-field fallback all came for free, and the French page
  rendered correctly at 375px on the first build.
- **`test_config.py` caught the untranslated scaffold copy immediately**, with a message that
  named the language and listed the nine offending keys. That is exactly the guardrail D2 asks
  for, working as designed.
- **The MCP server needed nothing.** `smoke_test` went green against the fork's `items.json`
  with all seven tools, including a French `get_item`, without a single edit.
- **The `sitemap` fetcher is the unsung hero.** It fetches each page and filters on its *text*,
  which is why it found 60 real Ontario consultations inside a 95,000-URL sitemap when the two
  `html_index` sources found nothing.
- **FORKING.md's fetcher reference is accurate.** Every field I used behaved as documented;
  the gaps are omissions, not errors.

## 5. What could have gone better

Ranked by how much time each cost me.

1. **The red-on-arrival suite (friction 2 and 3).** About 10 minutes, and the only thing that
   forced a Python/test edit. It also means a fork that follows the checklist exactly and then
   pushes will watch its first workflow run fail. Highest-value fix in the whole list.
2. **Reverse-engineering the `text.<lang>` keys and `official_names` (friction 4 and 5).**
   About 8 minutes of diffing against the parent checkout. Entirely self-inflicted by the
   scaffold's comment-stripping; fixing friction 5 fixes both.
3. **Discovering `html_index`'s title-only filter (friction 9).** About 8 minutes of writing
   selectors that were correct and yielded nothing. A one-sentence caveat in FORKING.md would
   have redirected me to `sitemap` immediately.
4. **The silent-zero column typo (friction 8).** About 5 minutes, and the reason I could not
   tell a broken mapping from a genuinely empty source while tuning the CKAN query.
5. **The pre-filter's word-boundary wrapper (friction 6).** About 4 minutes to diagnose, but
   the cost to the *original* site is larger than the cost to me: two shipped French keywords
   have never matched anything.
