# Fork attempt — Québec (provincial), French-primary

Tester: outside coder, no contact with the author. Clone of `Canadian Governance Monitor`
at commit `cfcb75e`. Target: **Québec**, provincial, `--languages fr,en --locale fr=fr-CA
--locale en=en-CA`. Site name **« Échéances des consultations sur l'IA Québec »**.

Clock: clone at **19:34:38**, first rendered site from real curated items with the suite
green apart from one pre-existing test failure at **19:57:20**. **~23 minutes**, plus about
15 minutes of source hunting (excluded by the rubric). Whole exercise including every rubric
check finished around 20:10.

---

## 1. Summary

It worked. A newcomer can stand up a French-primary Québec fork from `docs/FORKING.md`
alone in well under half an hour, editing only `data/site.yaml`, `data/sources.yaml` and
`data/items.json`, with no Python, template or test edits.

Three of the four headline thresholds pass: files edited (three data files, nothing else),
zero Python/test edits, 23 minutes to a green build against a two-hour target.

The fourth threshold **fails**: the suite is **not** green after the scaffold. A
French-primary fork whose *secondary* language is `en` trips `tests/test_fetch.py`, whose
fixture uses literal `title_en` / `description_en` column names that collide with the
secondary-language suffix. One test, red from the first minute to the last, and the deploy
workflow would refuse to publish because of it.

Two smaller French-primary defects: the meta description and `llms.txt` are English sentence
frames with French fragments dropped into them, and the server-rendered dates ignore
`date_style: long`, so the first paint of the French page shows ISO dates.

Author questions that had to be guessed rather than asked: **0 blocking**, 5 logged.

## 3. Friction log

### 1. The suite is red from the first minute on any fork whose secondary language is en — BLOCKING

**What happened.** `python -m pytest` immediately after the scaffold, before a single hand
edit:

```
FAILED tests/test_fetch.py::test_missing_id_falls_back_to_a_title_slug_and_missing_url_to_the_portal
E  AssertionError: assert False
E   +  where False = 'reg-titre-en'.startswith('reg-consultation-on-artificial')
```

**Where.** tests/test_fetch.py, lines 7 to 29.

**Why.** The fixture hardcodes the column names title_en and description_en, then adds
row["title_" + x] = "Titre " + x for every x in SECONDARY. On the shipped site SECONDARY is
["fr"], so title_fr is added and title_en survives. On a French-primary fork SECONDARY is
["en"], so the loop overwrites title_en with "Titre en" and the id falls back to
reg-titre-en. The fetcher is fine; the fixture collides with itself.

The message does not point at the cause at all — a newcomer reads it as "the id fallback is
broken" and starts reading fetch.py. I spent about six minutes there before spotting the
SECONDARY loop, and only proved it by running the monolingual scaffold (D1), where the
failure vanishes.

**What I did instead.** Left it red for the whole exercise and ran the other checks with
--deselect. I did not edit tests/ — the rubric forbids it and so does the promise.

**Fix.** Rename the fixture columns to language-neutral names so they cannot collide with a
field_lang suffix — for example col_title, col_url, col_desc, with the secondary map becoming
{"title_" + x: "t_" + x for x in SECONDARY} — and change _row() to match. Then add a case (in
test_fork.py, which already scaffolds forks in a subprocess) that runs the suite for
--languages fr,en, so a language-pair inversion is caught the way the monolingual case
already is.

**Severity.** Blocking: daily.yml runs pytest before anything else, so this fork cannot
deploy at all until it is fixed.

### 2. A non-ASCII site name produces a mangled slug, and --slug is not in the docs

**What happened.** The dry run with the name "Échéances des consultations sur l'IA Québec":

```
slug='ch-ances-des-consultations-sur-l-ia-qu-bec'
```

Accented characters are dropped rather than transliterated, so "Échéances" becomes "ch-ances"
and "Québec" becomes "qu-bec". The slug is the feed generator id, the calendar UIDs and the
fetchers' user agent — three places where that string is public.

**Where.** python -m pipeline.fork, slug derivation.

**What I did instead.** python -m pipeline.fork --help showed a --slug flag that
docs/FORKING.md never mentions (nor --year or --root). Passed
--slug echeances-consultations-ia-quebec.

**Fix.** Two lines. (a) Transliterate before slugging: NFKD-normalise and drop the combining
marks, which turns "Échéances Québec" into "echeances-quebec". (b) Add --slug, --year and
--root to the FORKING.md step-2 example, or at least to the key reference. The dry run is a
good place to warn: if the derived slug differs from a transliteration of the name, say so.

### 3. The meta description and llms.txt are English sentence frames with French words dropped in — B2 fail

**What happened.** The rendered French page carries a meta description reading, verbatim:

"Tracking 3 consultations provinciales, appels de mémoires, périodes de commentaires
réglementaires, appels de projets et pétitions à l'Assemblée nationale where la population du
Québec can shape AI governance. 2 open now, 0 closing within 7 days. Each one has a
plain-language summary and a concrete way to take part. Updated deux fois par semaine."

and llms.txt opens with "Every channel through which la population du Québec can shape how AI
is governed -- consultations provinciales, appels de mémoires ... each with a plain-language
summary".

**Where.** pipeline/build.py lines 363-365 (meta plus schema.org description), 209 (the same
frame elsewhere) and 717 (the digest and llms lead). These are English sentences in Python
that get text.channels, text.audience and text.cadence — all primary-language prose —
interpolated into them.

digest.md is correct French, because it builds its headings from pipeline/strings/fr.yaml.
So the pattern already exists; these three frames just missed it.

**What I did instead.** Nothing available. Writing English channels/audience/cadence values
would have fixed the meta description and broken the visible French page, since the same keys
feed the tagline and the .ics description. Left it as franglais.

**Fix.** Move the three frames into the strings files as templates with placeholders — an
en.yaml meta_description key and its French equivalent in fr.yaml — then render with the
primary language's template. This is the single change that most affects how a non-English
fork looks to a search engine.

### 4. Server-rendered dates ignore date_style, so the French page's first paint is ISO — D4

**What happened.** With date_style: long in fr.yaml and locales.fr: fr-CA, the page as served
shows "Ouvert le 2025-12-05" and "Clôturé 2024-10-31". Typing anything into the search box
re-renders the list and the same dates become "5 déc. 2025" and "31 oct. 2024".

**Where.** pipeline/build.py writes the time elements server-side with the raw ISO string;
pipeline/template.html line 249's fmtDate applies Intl.DateTimeFormat(CFG.locales[lang]) but
only when the client re-renders the list, which does not happen on load.

I verified in the live page that fmtDate returns "5 déc. 2025" for that date, so the config is
being read correctly — it is just never applied to the initial markup.

**Why it only bites forks.** The shipped English site has date_style: iso, so the
server-rendered ISO string is already the right answer and the bug is invisible.

**Fix.** Either format the dates in build.py for the primary language (a twelve-entry month
list per strings file avoids a Babel dependency), or call the client renderer once on
DOMContentLoaded. The first is better — it also fixes the no-JS view and the value a search
engine indexes.

### 5. A misspelt kind raises a raw traceback

**What happened.** Setting kind to json-api instead of json_api produced an eleven-line Python
traceback ending in:

ValueError: data/sources.yaml: source 'donnees_quebec' has kind 'json-api'; valid kinds are
['csv', 'html_index', 'json_api', 'rss', 'sitemap']

The message is exactly right — file, key, bad value, valid values. It is buried under a
traceback, which rubric C2 explicitly rules out.

By contrast the wrong-column case is a model of what this should look like:

```
donnees_quebec: column 'titre_officiel' is empty or missing in the first open row; row has:
['author', 'author_email', 'creator_user_id', 'doi', 'ext_spatial', ...]
donnees_quebec                  0 candidates
```

**Fix.** Catch config errors in main() and exit with a plain "error:" line. One try/except.

### 6. test_store.py rejects the url_template pattern that FORKING.md recommends

**What happened.** FORKING.md says, of a registry that publishes a slug but no link, that it
can carry a url_template on the source with a placeholder for the slug field. Données Québec
is exactly that CKAN case, so I wrote url_template and no columns.url. pipeline.fetch handled
it perfectly — all seven candidates got correct URLs — and then the suite went red:

```
AssertionError: donnees_quebec: columns need at least title and url
tests/test_store.py:92
```

**What I did instead.** Declared "url: url" (the CKAN field exists and is empty on every row)
purely to satisfy the test, with a comment in sources.yaml explaining that it is there for the
test and url_template does the real work. That is a lie in the config file to appease a test,
which is a bad thing to leave in a fork.

**Fix.** Make the assertion accept url_template or portal as an alternative to columns.url.
Cost: one line. It cost me about four minutes and left a wart in my config.

### 7. Passing --help to pipeline.fetch writes a file called --help

**What happened.** Reaching for the usual reflex after seeing 0 candidates from one source, I
ran pipeline.fetch with --help. fetch.py takes sys.argv[1] as the output path, so it fetched
every source and reported "wrote 10 candidates -> --help", leaving a file literally named
--help in the repo root — one that needs a guard to delete and that a fork author could easily
commit.

**Fix.** Give fetch.py an argparse parser like fork.py has, or at minimum reject an output
path starting with a dash. classify.py already handles --print-prompt, so the inconsistency is
surprising.

### 8. The rubric's own B1 grep cannot pass

**What happened.** Running the command B1 specifies returns 30+ lines, of which none are real
defects except one:

- "gazette" is a member of the closed type vocabulary (gazette_notice in models.py,
  classify.py, both strings files, the MCP tool docs). It is a channel kind, not a place. It
  can never be removed and should not be.
- tests/test_fork.py and tests/test_template.py name the parent place and the author's handle
  on purpose, as the guards that enforce B1 in the first place.
- __pycache__ binaries match and dominate the output.

The one genuine hit: tests/conftest.py lines 29 and 36 give fixture items the body
"Innovation, Science & Economic Development Canada" and its French equivalent. Harmless, but
it means every fork ships tests that name the parent country in their data.

**Fix.** Rewrite the criterion's command to exclude __pycache__, test_fork.py and
test_template.py, and neutralise the conftest.py fixture bodies to something like "Ministry of
Example".

### 9. version is the one undocumented site.yaml key

The version key (scaffolded as 0.1) has no comment in the generated file and no row in
FORKING.md's key reference. It surfaces publicly: it is embedded in the calendar PRODID and it
lands in the JS CFG blob. A fork author needs to know whether to bump it and what it means. I
guessed "site version, bump when you like" and moved on.

**Fix.** One comment line, or one row in the key table.

### 10. FORKING.md never addresses a non-English primary language

This is the question I would have asked the author. The scaffold's own checklist is honest
about it — "rewrite the generated draft (English, whatever your primary language)" — but
FORKING.md's step 3 buries that in a clause and never says what follows for a French-primary
site: that the generated primary block is entirely English prose under a French title, that
page_title comes out half and half, and that test_config.py's untranslated-copy check only
guards the secondary block, so nothing catches a primary block left in the scaffold's English.

Related, and the reason I could not verify a convention: the item schema's unsuffixed fields
hold the primary language. The title field is French in this fork and title_en is English.
That is a good design and it is nowhere stated in FORKING.md; I inferred it from the shipped
items.json before hand-writing my three items. If I had guessed the other way, every item I
wrote would have been backwards.

**Fix.** A short "If your primary language is not English" subsection in FORKING.md: the
scaffolded prose is an English draft to be replaced wholesale, the unsuffixed item fields
carry the primary language, and set date_style in your primary strings file (friction 4).

### 11. Minor: an English aria-label, and official_names punctuation

- pipeline/template.html line 192 renders the language toggle with a hardcoded
  aria-label="Language" — an English accessible name on a French page, including on a
  monolingual French site where it labels an empty element. It should come from the strings
  file.
- The prompt dump shows my classifier.official_names value concatenated into an English
  sentence and terminated with a doubled full stop, because the builder appends a period to a
  value that already ends in one. Cosmetic; FORKING.md could say whether the value should be a
  bare clause.

## 4. What went well

- **The three-file promise holds.** git diff --stat shows changes to data/site.yaml,
  data/sources.yaml, data/items.json and the regenerated site/. No Python, no template, no
  tests. That is the headline claim and it survives contact with a genuinely different
  jurisdiction and a language inversion.
- **The commented site.yaml is the best part of the repo.** Almost every key answered its own
  question at the point of use; I opened FORKING.md's key table twice, not twenty times.
- **The scaffold's checklist adapts to the fork.** "Translate the block for: en." and "(UI
  strings for every configured language already exist in pipeline/strings/.)" are both computed
  from --languages, and both were exactly right.
- **The dry run was trustworthy.** Five lines plus the checklist, matched the real run word
  for word.
- **The fetcher error for a wrong column name** is the best diagnostic I have seen in a project
  like this: it names the source, the column, and the row's real keys. It found my mistake
  instantly.
- **--print-prompt without an API key.** With no key in this environment, E1 would have been
  untestable without it. The prompt it produced was clean Québec content with zero parent
  residue.
- **The build survives an all-null-deadline store.** Three items, none with a future closing
  date: the calendar still validates, the digest says "Rien cette semaine" in French, the stat
  tiles read 0 / 2 / 0 / 1. Nothing degraded into an error.
- **The rendered French site looks genuinely good** at both widths, with a site name half again
  as long as the original's, and the language toggle switches html lang, title, h1, item
  titles, badges and date style correctly.
- **test_config.py's untranslated-copy check** is a smart guard and it fired exactly as
  documented.

## 5. What could have gone better, ranked by time cost

1. **test_fetch.py's _en fixture collision (about 12 minutes, and permanently blocking).** Six
   minutes reading fetch.py for a bug that was not there, then the monolingual run to prove the
   cause. Worse than the time: the fork cannot deploy, because daily.yml gates on the suite.
   Highest-value fix in this report.
2. **Hunting Québec sources (about 15 minutes, excluded from the threshold but real).** Three
   promising leads were dead ends: quebec.ca/sitemap.xml is a 770-URL index of news and generic
   pages with zero consultation URLs; the Assemblée nationale's mandats-encours page injects
   every mandate link in JavaScript, so html_index sees nothing; assnat.qc.ca/sitemap.xml is
   402 static pages with no bills. Not the repo's fault, but a "before you write a source, curl
   the URL and grep it" line in FORKING.md's fetcher section would have saved two of the three.
3. **The url_template / test_store.py contradiction (about 4 minutes plus a permanent wart).**
   Doing what the docs recommend turned the suite red, and the fix I could apply without
   editing tests is a fake column mapping.
4. **The franglais meta description (about 3 minutes to diagnose, unfixable from config).** The
   most visible remaining defect on the published fork.
5. **Slug mangling and the undocumented --slug (about 2 minutes).** Caught only because I dry-
   ran first, which is itself an argument for the docs telling you to.
6. **ISO dates on first paint (about 2 minutes).** Cosmetic, but it is the first thing a French
   reader sees.
7. **The --help file (about 1 minute).** Trivial, but it writes junk into the repo root while
   spending 40 seconds of network I/O.
